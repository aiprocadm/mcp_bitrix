# ChatGPT: факты и ограничения (ТЗ §18.4–18.5)

Состояние на 2026-09-24: подключение ChatGPT **не проверялось** (`blocked`). Серверная часть готова
(`MCP_AUTH_MODE=oauth`, метаданные RFC 9728, проверка токенов — `docs/deployment.md`), но:

1. ChatGPT подключается только к удалённому MCP по HTTPS с OAuth-входом: нужен домен, сертификат и authorization
   server заказчика. Локальный `stdio`, файл `.env` и `http://127.0.0.1:3000` в облачный ChatGPT вставить нельзя —
   это не адрес, который он может открыть.
2. Возможность создать своё MCP-приложение зависит от аккаунта и рабочего пространства (Developer mode, политика
   организации). Её наличие проверяется в самом аккаунте заказчика, по названию тарифа обещать нельзя.
3. Секретный URL вебхука Bitrix24 — не адрес MCP-сервера. Его никуда не вставляют.

## Что ещё нужно перед проверкой

- Публикация по `docs/deployment.md` (nginx, `examples/remote.env.example`), AS с регистрацией клиента (Client ID
  Metadata Documents или Dynamic Client Registration — так подключается ChatGPT), PKCE, `aud` = адрес сервера,
  `sub` пользователя в `MCP_AUTH_ALLOWED_SUBJECTS`.
- Для записей из ChatGPT: панель владельца `/admin` (`ADMIN_PANEL_ENABLED=true`, `docs/operations.md`) — там
  подтверждаются планы и готовятся файлы (`fileToken`); при `UPLOAD_SCAN_REQUIRED=true` нужен ClamAV.
- Реальное подключение в аккаунте заказчика: минимум один вызов чтения, затем одна подтверждённая запись.
  Работа Claude Code не считается доказательством работы ChatGPT.

## Алгоритм проверки в аккаунте (когда сервер будет опубликован)

1. Веб-версия ChatGPT под нужным аккаунтом → настройки → Developer mode (или Apps/Advanced в организации).
2. Создать своё приложение/MCP, указать `https://<домен>/mcp` и пройти OAuth-вход разрешённым пользователем.
3. Проверить список инструментов, выполнить `bitrix_connection_info` и одно чтение.
4. Запись — только после подтверждения на сервере (план → подтверждение владельцем → повтор с `approvalId`).
5. Зафиксировать в `docs/acceptance-report.md`: дата, клиент, что сработало, что нет.

## Если прямое подключение недоступно

| Вариант                                                                   | Что даёт                                           | Что нужно дополнительно                                                                    |
| ------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Claude Code / Claude Desktop                                              | Полноценная работа с локальным сервером уже сейчас | Только установленный клиент                                                                |
| Собственное приложение с OpenAI Responses API (`type: mcp`, `server_url`) | Вызовы удалённого MCP из своего кода               | Отдельный проект, ключ API, биллинг, обработка подтверждений; тот же опубликованный сервер |
| OpenAPI/GPT Actions слой поверх сервисного слоя                           | Вызовы из custom GPT                               | Отдельный слой поверх того же MutationExecutor, HTTPS и auth; это не MCP                   |

Ни один из вариантов не обходит подтверждения: любая запись всё равно проходит через план и решение человека.
