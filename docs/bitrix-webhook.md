# Входящий вебхук Bitrix24 (ТЗ §6.1, §7.2)

Вебхук — это специальная ссылка, по которой наш сервер обращается к вашему Битрикс24 от имени
выбранного сотрудника. Кто знает ссылку — тот действует от имени этого сотрудника, поэтому она секретная.

## Создание

1. Войдите в портал под сотрудником, от имени которого будет работать интеграция.
2. **Приложения → Разработчикам → Готовые сценарии → Другое → Входящий вебхук** (названия пунктов могут отличаться; ищите «вебхук» в поиске меню).
3. Назовите, например, `MCP — личная интеграция`.
4. Права (scope) для MVP: **CRM (`crm`)**, **Задачи (`task`)**, **Чат и уведомления (`im`)**, **Диск (`disk`)**, **Календарь (`calendar`)**. Для проверки связи достаточно ничего не отмечать: метод `profile` работает без scope. Не включайте всё подряд.
5. Сохраните. Скопируйте **базовый URL** вида:

```
https://ваш-портал.bitrix24.ru/rest/<userId>/<код>/
```

Если генератор показал ссылку с методом (`.../profile.json`), уберите имя метода и оставьте завершающий `/`.

## Заполнение `.env`

```dotenv
BITRIX_PORTAL_URL=https://ваш-портал.bitrix24.ru
BITRIX_WEBHOOK_BASE_URL=https://ваш-портал.bitrix24.ru/rest/<userId>/<код>/
```

Origin обеих строк должен совпадать; иначе `npm run doctor` сообщит `CONFIG_INVALID` (значение не печатается).

## Правила

- Ссылку не отправлять в чат Claude/ChatGPT, не прикреплять к скриншотам, не коммитить.
- Файл `.env` — права `600` (Linux) или ACL только для вашей учётной записи (Windows).
- При утечке: удалить вебхук в портале и создать новый. Смена пароля сотрудника не отзывает вебхук.
- Права вебхука ограничены правами сотрудника: если он не видит сделку в интерфейсе, сервер её тоже не увидит и обходить это не будет.

## Проверка

```bash
npm run doctor            # profile, список scope, доступность MVP-методов
npm run bitrix:profile    # один запрос profile, вывод без секретов
```

Типовые ошибки — `docs/troubleshooting.md`.
