# Если не работает (ТЗ §7.5)

| Симптом                                                            | Что проверить и сделать                                                                                                                                                                        |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[CONFIG_INVALID] BITRIX_WEBHOOK_BASE_URL: ...`                    | Формат `https://портал/rest/<userId>/<код>/`, origin совпадает с `BITRIX_PORTAL_URL`, нет имени метода и `?`. Значение в сообщении не печатается намеренно                                     |
| `[CONFIG_INVALID] READ_ONLY_MODE: допустимы только true или false` | В `.env` только `true`/`false`, без `yes`/`1`                                                                                                                                                  |
| `Ключ шифрования не найден`                                        | `npm run setup`                                                                                                                                                                                |
| `Файл политики не найден`                                          | `npm run setup` создаст `policies/*.json` из примеров                                                                                                                                          |
| `doctor`: `profile FAIL BITRIX_AUTH_FAILED`                        | Вебхук удалён/пересоздан или URL скопирован с ошибкой. Проверьте в портале, пересоздайте, обновите `.env`                                                                                      |
| `BITRIX_SCOPE_MISSING`                                             | В настройках вебхука не отмечен нужный раздел (crm/task/im/disk/calendar). Добавьте только нужный, сохраните, снова `npm run doctor`                                                           |
| `BITRIX_ACCESS_DENIED`                                             | Права самого сотрудника на объект; проверьте под тем же пользователем в интерфейсе. Сервер это не обходит                                                                                      |
| `BITRIX_APP_CONTEXT_REQUIRED` (`WRONG_AUTH_TYPE`)                  | Метод требует локального приложения, вебхук не подходит; это отдельный этап (OAuth)                                                                                                            |
| `FEATURE_UNAVAILABLE`                                              | Метод/модуль недоступен на портале или тарифе; `bitrix_capabilities` покажет по методам                                                                                                        |
| `METHOD_NOT_ALLOWED` в `bitrix_rest_call`                          | Метод не в allowlist `policies/methods.json` или не читающий. Расширять allowlist — решение владельца                                                                                          |
| `BITRIX_RATE_LIMITED`                                              | Портал ограничил частоту; подождите, уменьшите объём запросов                                                                                                                                  |
| Claude Code не видит инструменты                                   | `npm run build`, `claude mcp get bitrix24`, `npm run mcp:smoke -- --transport stdio`; абсолютные пути в команде add                                                                            |
| Нет пункта «Входящий вебхук»                                       | Права на интеграции/REST-доступ по тарифу. Через cookies браузера сервер не работает принципиально                                                                                             |
| Ответ `APPROVAL_REQUIRED`                                          | Запись ещё не выполнена. В терминале: `npm run approval:review -- --id <operationId>`, введите ПОДТВЕРЖДАЮ, затем повторите вызов с теми же параметрами и `approvalId`                         |
| `APPROVAL_EXPIRED` / `APPROVAL_MISMATCH`                           | Срок 10 минут истёк или параметры/ключ/оператор не совпали с планом: подготовьте новый план тем же вызовом без `approvalId`                                                                    |
| `IDEMPOTENCY_CONFLICT`                                             | Тот же `idempotencyKey` уже был с другими параметрами; для нового действия нужен новый ключ                                                                                                    |
| `OPERATION_OUTCOME_UNKNOWN`                                        | Ответ Bitrix24 на запись потерян; проверьте объект в интерфейсе, повтор не делайте вслепую (`operation_status` покажет состояние)                                                              |
| `UNSAFE_FILE` / `FILE_TOO_LARGE`                                   | Файл должен лежать в `UPLOAD_ROOT`, быть txt/md/csv/pdf/docx/xlsx/png/jpg до 10 МиБ, без симлинков; `npm run file:stage -- --path <абс. путь>`                                                 |
| `approval:review` пишет «только в интерактивном терминале»         | Команда намеренно не принимает ввод через pipe/скрипт; запустите её вручную                                                                                                                    |
| `test:live` пишет «Живые тесты выключены»                          | Это защита: `LIVE_TESTS_ENABLED=true` включайте только для согласованного тестового портала; для записи ещё нужны `TEST_*` цели и `READ_ONLY_MODE=false`                                       |
| `test:live --write --execute` показывает BLOCK                     | Планы не подтверждены: выполните `npm run approval:review -- --id <operationId>` для каждого из отчёта `data/live-smoke-report.json`                                                           |
| `backup --restore` пишет «ключ не подходит»                        | Копия зашифрована ключом из `SECRETS_KEY_FILE` того сервера, где создана; восстановите сначала ключ                                                                                            |
| Контейнер не стартует с `CONFIG_INVALID MCP_HOST`                  | Внешний интерфейс при `MCP_AUTH_MODE=local` запрещён; в `compose.yaml` используется `network_mode: host` и `MCP_HOST=127.0.0.1`, наружу — только через nginx                                   |
| `/mcp` отвечает 401 при верном токене                              | Сравните `iss`/`aud` токена с `MCP_AUTH_ISSUER`/`MCP_PUBLIC_URL` (точная строка, без завершающего `/`), срок `exp`, `kid` в JWKS; причина — в `error_description` заголовка `WWW-Authenticate` |
| `/mcp` отвечает 403 `access_denied`                                | `sub` токена не в `MCP_AUTH_ALLOWED_SUBJECTS`, либо запрос к чужой сессии, либо `Origin` не в `MCP_ALLOWED_ORIGINS`                                                                            |
| `/mcp` отвечает 403 `insufficient_scope`                           | Токен без scope `read`/`write`/`admin`: настройте scope у клиента в authorization server                                                                                                       |
| `/mcp` отвечает 503 `server_error`                                 | Сервер не смог получить JWKS по `MCP_AUTH_JWKS_URI`: проверьте доступность authorization server с VPS                                                                                          |
| Инструменты записи не видны удалённому клиенту                     | Роль = min(policy, scope): добавьте `sub` в `policies/access.json` с ролью operator/administrator и выдайте scope `write`/`admin`                                                              |
| Ответ `RATE_LIMITED`                                               | Превышен `MCP_INBOUND_READ_PER_MINUTE` (60/мин) или 10 write-подготовок в минуту; подождите минуту                                                                                             |
| `/admin/login` отвечает 404                                        | `ADMIN_PANEL_ENABLED=true` и `MCP_TRANSPORT=http` не заданы; после изменения перезапустите сервер                                                                                              |
| Панель: «Запрос пришёл не с этой панели» или «Форма устарела»      | Проверка CSRF: `Origin` должен совпадать с `MCP_PUBLIC_URL` (nginx передаёт `Origin` без изменений), форма открыта заново после входа                                                          |
| Панель: «Ваша роль не позволяет решать по этому плану»             | Чужие планы подтверждает только роль administrator; роль берётся из `policies/access.json` по `--principal` пользователя                                                                       |
| Загрузка: «сканер недоступен; загрузка заблокирована»              | `UPLOAD_SCAN_REQUIRED=true`, а clamd по `UPLOAD_SCANNER_URL` не отвечает: `npm run doctor` (строка `file scanner`), проверьте службу ClamAV                                                    |
| Загрузка: «отклонён антивирусом»                                   | Файл содержит сигнатуру из базы ClamAV; это ожидаемое поведение, файл не сохранён                                                                                                              |

Для обращения за помощью достаточно кода ошибки и `requestId` из ответа; секрет вебхука никому не отправляйте.
