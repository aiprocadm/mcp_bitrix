## Что именно сделано (срез 8, этап 12 — часть 1: удалённый доступ)

- **OAuth-защита MCP** (`src/auth/mcp-auth.ts`, по спецификации MCP Authorization S25): сервер — resource server. На каждом запросе к `/mcp` и `/readyz` проверяются подпись по JWKS издателя (`jose`, `createRemoteJWKSet` по явно настроенному `MCP_AUTH_JWKS_URI`), `iss` (точная строка), `aud` (= канонический `MCP_PUBLIC_URL` без `/`, RFC 8707), `exp`/`iat`/`sub`, `sub` ∈ `MCP_AUTH_ALLOWED_SUBJECTS`, scope `read`/`write`/`admin` (`scope` или `scp`). Роль сессии = min(роль в `access.json`, роль по scope; неизвестный субъект — reader). Ответы: 401 `invalid_token` + `WWW-Authenticate: Bearer resource_metadata=…` (описание в заголовке — только ASCII), 403 `access_denied`/`insufficient_scope`, 400 токен в query, 503 `server_error` при недоступном JWKS (без челленджа). Документ RFC 9728 на `/.well-known/oauth-protected-resource[/mcp]`.
- HTTP-транспорт (`src/mcp/http.ts`): принципал на сессию (`createMcpServer(app, {principal})`, `registerTools(server, app, principal)`), сессия привязана к субъекту (чужой токен → 403), `Origin` браузеров по `MCP_ALLOWED_ORIGINS` + origin публичного адреса (адаптер Fastify сверяет hostname, наш `originAllowed` — точный origin), `/readyz` под токеном, `Host` по умолчанию = хост `MCP_PUBLIC_URL`.
- Конфиг (`src/config/env.ts`): `MCP_AUTH_MODE=oauth` больше не отвергается; требует http-транспорт, `MCP_PUBLIC_URL`/`MCP_AUTH_ISSUER`/`MCP_AUTH_JWKS_URI` (https, http только для loopback, без учётных данных и fragment), непустой allowlist. `MCP_AUTH_AUDIENCE` по умолчанию = resource. Новая `MCP_INBOUND_READ_PER_MINUTE` (60; §8.6) — `src/security/inbound-limiter.ts` в диспетчере для всех транспортов (write-подготовки по-прежнему 10/мин в MutationExecutor); `mock.env` ставит 100000, чтобы не ломать тесты.
- `npm run mcp:smoke -- --transport http --url https://…/mcp` — удалённый smoke с bearer-токеном из переменной окружения (`--token-env`, по умолчанию `MCP_SMOKE_TOKEN`), только https (http — loopback).
- `deploy/nginx/mcp.conf.example`, `examples/remote.env.example`; документы: `deployment.md` (требования к authorization server, шаги, что проверено/нет), `claude-code.md` (§18.3), `chatgpt.md`, `troubleshooting.md` (+6 строк), README.
- Тесты: +15 (195): `tests/security/mcp-oauth.test.ts` (T39: без токена/просрочен/чужие aud, iss, ключ/мусор/Basic/токен в query; allowlist и scope; роль по policy×scope; T40: привязка сессии, чужой/`null`/разрешённый Origin; readyz; псевдонимы в аудите; JWKS по настоящему HTTP на loopback; JWKS недоступен → 503), `tests/unit/mcp-auth-config.test.ts`, `tests/security/inbound-limit.test.ts`.
- Живая проверка на loopback: локальный издатель (JWKS по HTTP) → сервер в режиме oauth → curl 401 с челленджем, метаданные, просроченный токен → 401, `mcp:smoke --url` без токена — отказ, с токеном — OK, `/readyz` с токеном — 200.
- Не проверено (`not-run`): реальный домен/TLS, реальный authorization server (Keycloak и т. п.), регистрация клиентов Claude Code/ChatGPT (CIMD/DCR), реальный портал. Панель `/admin`, web-upload, сканер — срез 9.

## Что именно сделано (срез 2, этап 6)

- `MutationExecutor` (`src/security/mutation-executor.ts`) — единственная точка записи. Порядок: аудит доступен → dryRun (только план) → idempotencyKey обязателен → повтор по ключу (replay / unknown / conflict / тот же план) → без approvalId `APPROVAL_REQUIRED` с operationId и планом → с approvalId сверка principal/portal/tool/argsHash/policyVersion/stateHash/fileHash/ключа, атомарный переход approved→executing, precheck (CONFLICT), perform, verify, результат в ledger (зашифрован). Одновременные вызовы с одним ключом делят одно выполнение (T08). Лимит 10 подготовок/мин на оператора.
- `ApprovalService` — prepare/readPlan/approve/deny/listPending; планы в SQLite зашифрованы (AES-GCM, AAD = operationId), TTL 10 мин.
- Ledger (`storage/operations.ts`): состояния prepared→approved→executing→succeeded/failed/unknown, denied, expired; после рестарта executing→unknown (T16); таблица idempotency с TTL 7 дней.

- CLI: `npm run approval:review -- --id <id>` (план целиком, ввод слова ПОДТВЕРЖДАЮ/ОТКЛОНЯЮ, без `--yes`, отказ без TTY), `--list`; `npm run file:stage -- --path <абс. путь>`.

## Грабли (чтобы не наступать дважды)

- `npm install` не запускает postinstall esbuild (политика allowScripts) → `tsx` не работает. Решено записью `allowScripts` в `package.json`; при чистой установке выполнять `npm ci` — она её учитывает.
- SDK v2 не экспортирует `package.json` через `exports` — версию читаем файлом (`src/version.ts`).
- `dist/` нужно пересобирать перед `mcp:smoke --transport stdio`: smoke предпочитает `dist/index.js`, если он есть.
- Политика выдачи сопоставляет имена полей **с учётом регистра**: шаблон `^AUTH` для Bitrix-полей не должен вырезать наше `authMode`.
- `fetch` в Node не даёт подменить заголовок `Host` — тест DNS-rebinding идёт через `node:http`.
- `fastify.close()` виснет на открытых SSE-соединениях — перед закрытием `server.closeAllConnections()`.
- Vitest: `console.log` в тестах не показывается в кратком выводе; для отладки писать в файл.
- Guard worktree в этой среде отклоняет сложные bash-команды с `cd`/heredoc/переменными в путях/конвейерами — файлы писать инструментом Write, команды разбивать, пути писать буквально.
- Прямая проверка «CLI не принимает ввод через pipe» из bash невозможна (guard) — она живёт тестом `tests/security/approval-cli-no-tty.test.ts`, который сам запускает CLI.
- `data/` не в git: тесты, запускающие настоящий процесс, обязаны сами создавать ключ (`ensureMasterKey(..., {create:true})`), иначе на чистой копии `CONFIG_INVALID`.
- Редактор секретов применяется и к выводу CLI (`out()`): слишком широкий шаблон «телефона» ломал хеши и даты. Любой новый шаблон проверять на sha256/ISO-дате/UUID.
- `MCP_HOST=0.0.0.0` при `MCP_AUTH_MODE=local` отвергается конфигурацией — compose-профиль до этапа 12 живёт на `network_mode: host` с `127.0.0.1`; проверять `docker compose config` и реальный старт, а не только YAML. Docker на сервере доступен без sudo — compose гонять вживую (`MCP_PORT=3123`, порт 3000 хоста занят), одноразовые команды — `docker compose run --rm <service> node dist/cli/<cli>.js`, ENTRYPOINT в Dockerfile не ставить.
- Значения HTTP-заголовков — только ASCII: русское `error_description` в `WWW-Authenticate` молча ломало заголовок (Node отвергает не-Latin1). В `McpAuthError` отдельное поле `asciiDescription`; русский текст — только в теле.
- Адаптер `createMcpFastifyApp` для loopback-хоста сам отвергает любой не-localhost `Origin` — в oauth-режиме передавать `allowedOrigins` (hostname-ы) адаптеру, иначе разрешённый origin получит 403 до наших проверок.
- В журнале аудита не сырой `principal_id`, а `principal_hash` (HMAC-псевдоним, §8.1) — тесты сверяют различимость, не значение.
- `jose` ходит за JWKS сам (внутри `createRemoteJWKSet`); правило «fetch только в client.ts» проверяет наш исходник, а не зависимости — адрес JWKS задаётся только конфигурацией.
- Живые проверки с фоновыми процессами: их stdout нужно уводить в `/dev/null`, иначе конвейер `| head` ждёт вечно; результат писать в файл и читать после.
- После squash-слияния PR ветка worktree расходится с `main` — новый срез начинать в новом worktree от `origin/main`, старый не трогать из-под guard.
