# Открытые линии, генератор документов CRM, универсальные списки (2026-10-06)

Добавлено по заданию владельца после подключения живого портала. Удаления нет; запись — только создание документа
по шаблону, через план и подтверждение владельцем.

| Модуль `ENABLED_MODULES` | Scope вебхука | Инструменты                                                                                             |
| ------------------------ | ------------- | ------------------------------------------------------------------------------------------------------- |
| `openlines`              | `imopenlines` | `openlines_list`, `openlines_crm_chats`, `openlines_chat_history`                                       |
| `crm`                    | `crm`         | `crm_document_templates_list`, `crm_documents_list`, `crm_document_get`, `crm_document_create` (create) |
| `lists`                  | `lists`       | `lists_list`, `lists_fields_get`, `lists_elements_list`                                                 |

## Открытые линии

- `openlines_list` — `imopenlines.config.list.get` с `select: ID, LINE_NAME, ACTIVE`; очередь операторов не запрашивается.
- `openlines_crm_chats` — `imopenlines.crm.chat.get` по лиду/сделке/контакту/компании; запись CRM читается первой
  (метод на несуществующую запись отвечает пустым списком); по умолчанию все чаты (`ACTIVE_ONLY=N`).
- `openlines_chat_history` — `imopenlines.session.history.get` по `chatId` (последняя сессия) или `sessionId`:
  сообщения по времени, автор `client` (пользователь коннектора), `operator`, `system` (`senderid=0`), текст без BB-кодов,
  файлы — имя, тип, размер **без ссылок** (`urlDownload`/`urlShow` содержат доступ); привязки CRM из `entityData2`;
  `maxMessages` — последние N с пометкой неполноты.

## Генератор документов CRM

Живой портал: `crm.documentgenerator.template.list` отдаёт `result.templates` **объектом по ID** и поле
`downloadMachine` с **кодом вебхука в адресе**; документы — `downloadUrl`/`pdfUrl`/`…Machine`. Поэтому:

- все четыре метода закрыты для `bitrix_rest_call` (`rawCallable=false` в реестре, тест это фиксирует);
- инструменты отдают только белый список полей: шаблон — ID, название, привязка к типам записей, активность,
  нумератор, порядок; документ — ID, название, номер, шаблон, запись, дата, `pdfReady`, `hasPublicLink`;
  значения полей шаблона (`values`, там реквизиты клиента) не выдаются;
- `crm_document_create`: шаблон должен существовать (`NOT_FOUND`), быть активным (`TEMPLATE_INACTIVE`) и привязанным
  к типу записи (`TEMPLATE_ENTITY_MISMATCH`); запись CRM читается до плана; план показывает шаблон, запись, `values`
  и риск «счётчик нумератора увеличится»; в журнал операций пишутся только ID/название/номер; сверка — `document.get`
  (шаблон, запись, ошибка преобразования PDF). Ссылку на PDF сервер не выдаёт — документ открывается в карточке записи.
- Поддерживаемые записи: deal, lead, contact, company, quote (7), invoice (31) — по официальной странице `document.add`.
- **Привязки шаблонов (живой портал, не описано в документации):** `entityTypeId` шаблона — коды вида `1`, `7`,
  `2_category_0` (сделки воронки 0), `31_1` (счета воронки 1) и служебные (`16documentrealization`, классы провайдеров склада).
  Шаблон подходит записи, если привязан к её типу и, для привязки с воронкой, к её воронке (`dealCategoryIds` в списке,
  фильтр `dealCategoryId`); иначе `TEMPLATE_ENTITY_MISMATCH` с перечнем подходящих воронок. Служебные коды пропускаются.
- **Готовность PDF:** в списке документов — по `pdfId`; `document.get` поля `pdfId` не присылает — там по наличию `pdfUrl`
  и отсутствию ошибки преобразования (сама ссылка не выдаётся).

## Универсальные списки

- `lists_list` (`lists.get`, тип `lists` / `bitrix_processes` / `lists_socnet`), `lists_fields_get` (`lists.field.get`),
  `lists_elements_list` (`lists.element.get`, `nameContains` → `FILTER: {"%NAME": …}`): свойства `PROPERTY_N`
  подписаны названиями полей, варианты списка — текстом из `DISPLAY_VALUES_FORM`; поле без описания — кодом с предупреждением.
