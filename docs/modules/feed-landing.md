# Модуль: Лента и классическая база знаний (landing)

ТЗ: §9.10 (Лента, T35), §9.13 (классическая база знаний на landing, T36). Модули конфигурации: `feed`, `knowledgeBase`.

Код: `src/tools/feed/*` (Лента, общий санитайзер `sanitize.ts`), `src/tools/kb-legacy/*` (база знаний),
реестр методов — `src/bitrix/registry/feed-landing.ts`, список инструментов — `src/tools/registry/feed-landing.ts`.
Тесты: `tests/integration/feed.test.ts`, `tests/integration/kb-legacy.test.ts`.

## Очистка текста

`src/tools/feed/sanitize.ts`, без внешних зависимостей:

- `sanitizeHtml` (блоки базы знаний, `format=html`, `sanitizedHtml`): allowlist тегов и атрибутов; удаляются вместе с содержимым `script`, `style`, `iframe`, `object`, `embed`, `svg`, `math`, `noscript`, `template` и т. п. (повтор до устойчивости против `<scr<script>ipt>`); удаляются `on*`, `style`, `id`, опасные URL (`javascript:`, `vbscript:`, `data:`, обходы через управляющие символы/сущности); одиночные `<` экранируются.
- `sanitizeFeedText` (Лента, BBCode/текст): удаляются опасные элементы с содержимым, любые HTML-теги (текст остаётся), `[url]`/`[img]` с опасными URL; обычный текст с `<` не портится.
- Что удалено — перечисляется в рисках плана; в план попадает уже очищенный текст. Портал дополнительно чистит `CONTENT` блока сам.

## Ограничения, допущения и gaps

1. **Полная ветка комментариев новости — gap.** В документации (`log/blogcomment/index`) три метода: `log.blogcomment.add`, `log.blogcomment.user.get`, `log.blogcomment.delete`. Метода чтения всех комментариев поста (`log.blogcomment.get` и аналогов) нет. `log.blogcomment.user.get` возвращает `id`, `comment_id`, `log_id`, `date`, `text`, `attach` — поля ID поста нет, а `log_id` (запись журнала Ленты) документацией не сопоставлен с ID поста. Поэтому `postId` → `FULL_THREAD_UNAVAILABLE`. Альтернатива: интерфейс Bitrix24 или будущий документированный метод. Источник: https://apidocs.bitrix24.ru/api-reference/log/blogcomment/log-blogcomment-user-get.html
2. **Порядок выдачи `log.blogcomment.user.get` не документирован.** Курсор продолжает выборку по `LAST_ID = min(id)` страницы (вниз по ID); при восходящем порядке продолжение могло бы пропустить комментарии — это предупреждение в ответе. Совместное применение `FIRST_ID` и `LAST_ID` для этого метода не описано.
3. **Аудитория поста не читается.** `log.blogpost.get` не возвращает список получателей (только `HAS_SOCNET_ALL`), поэтому в diff `feed_post_update` «было» для аудитории — «неизвестно / все авторизованные». Сверка после записи — только по признаку «видно всем». `DEST` в `log.blogpost.update` трактуется как полная замена списка (в документации: «New list of recipients»).
4. **`authorId` в `feed_posts_list`** — локальный фильтр по `AUTHOR_ID`, у метода нет такого параметра; страница может быть короче `pageSize`.
5. **Код «HTML-блока» — gap.** Документация `landing.landing.addblock` требует `fields.CODE` из `landing.block.getrepository` и не называет универсального кода HTML/текстового блока (примеры — `02.three_cols_big_1`, `repo_<ID>`). Код не выдумывается: `blockCode` — входной параметр, проверяется по репозиторию в том же `scope` (`BLOCK_CODE_UNAVAILABLE`); без него инструмент возвращает `BLOCK_CODE_REQUIRED` со списком кодов раздела `text` портала. Как конкретный блок портала применяет произвольный `CONTENT` — проверяется только на реальном портале. Источник: https://apidocs.bitrix24.ru/api-reference/landing/page/block-methods/landing-landing-add-block.html
6. **Чтение статьи через `landing.block.getlist` с `get_content=true`,** а не поблочно `landing.block.getcontent`: один документированный вызов даёт ID, порядок и HTML всех блоков (N вызовов `getcontent` при лимите 1 запрос/с слишком дороги); хеш `stateHash` считается по тому же ответу. `landing.block.getcontent` в реестр не добавлен. Порядок блоков = порядок ответа (явной сортировки в документации нет).
7. **Черновик.** Все чтения/записи статей работают с черновиком (`edit_mode=true`); `landing.block.updatecontent` меняет черновик; `landing.landing.addblock` для опубликованной страницы виден после публикации — это указано в рисках.
8. **Видимость базы перед публикацией.** Документированных полей «публичный доступ базы» нет; проверяется тип сайта (KNOWLEDGE/GROUP — иначе отказ `NOT_KNOWLEDGE_BASE`), `ACTIVE` базы и папка статьи. По документации `landing.landing.publication` публикует папку, её родителей и делает сайт активным — это первые риски плана. Права доступа базы (`landing.site.getRights` — только права текущего пользователя) не читаются.
9. **`PARTIAL_SUCCESS`.** Составная запись (страница + блоки, или несколько блоков) при сбое после первого успешного шага сохраняет в ledger результат со статусами шагов и завершается `PARTIAL_SUCCESS` (коды ошибок — в `message`, так как `error.details` ограничен allowlist). Операция в ledger — `succeeded`, поэтому повтор (с `approvalId` или тем же ключом) возвращает тот же `PARTIAL_SUCCESS` без второго `landing.landing.add`; `verified=false`. Если не выполнен ни один шаг — обычная ошибка/unknown.
10. **Коды ошибок ТЗ** `AUDIENCE_REQUIRED`, `FULL_THREAD_UNAVAILABLE`, `CONTENT_TRUNCATED` отсутствуют в нормализованном наборе (`src/errors/app-error.ts`) и переданы как `reason` (`VALIDATION_ERROR`/`FEATURE_UNAVAILABLE`) и предупреждение `CONTENT_TRUNCATED` при `completeness=partial`.
11. **scope GROUP** — только на порталах с базами знаний групп (landing/types); создание базы GROUP не проверялось.

## Что проверено

- Mock (`tests/integration/feed.test.ts` — 14 тестов, `tests/integration/kb-legacy.test.ts` — 17 тестов): формы ответов по документации, параметры запросов, пагинация, AUDIENCE_REQUIRED, очистка script/iframe/on*, UA-риск, CONFLICT до плана и в precheck, T35 (coverage, FULL_THREAD_UNAVAILABLE), T36 (черновик, публикация не вызывается, порядок блоков), PARTIAL_SUCCESS без повторного `landing.landing.add`, полный путь approve/replay, OPERATION_OUTCOME_UNKNOWN, FEATURE_UNAVAILABLE, скрытие записи в READ_ONLY_MODE.
- Реальный портал: **not-run** (ни один метод `log.*`/`landing.*` на портале не вызывался; поведение `CONTENT` в выбранном блоке, регистр имён методов, порядок выдачи комментариев не подтверждены).
